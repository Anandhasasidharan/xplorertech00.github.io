Gatekeeper — every tool call meets the reference monitor

An AI agent plans a sequence of tool calls. Before each one runs, a reference monitor checks it against a deterministic capability policy: allowed, flagged, or blocked. This is the pattern from SENTRIX — a dual-LLM reference monitor that enforces capability policy before every tool call. The decisions here are computed live by the same policy and classifier rules ported from that project; the gate only renders them.

This browser has neither WebGPU nor WebGL 2. A still of the demo is shown below.

    Data source. Tool names, arguments, payload wording, the capability policy and the classifier patterns are taken from SENTRIX (examples/demo.py, src/sentrix/models/policy.py, src/sentrix/classifier/detector.py, src/sentrix/harness/obfuscator.py). The order in which the calls arrive, the lane assignment and the short per-call notes are illustrative sample data composed for this demo. Verdicts and reasons are computed live in your browser by the ported policy and classifier code, not hard-coded. No secrets, tokens or live scan results are included.

    Simplified port. This classifier is a simplified port: it uses SENTRIX's pattern matching only and does not include the project's embedding classifier, so it recognises known patterns rather than paraphrases.

    Rendering. Three.js with vanilla JavaScript; WebGPU where the browser supports it, WebGL 2 otherwise. Drag to orbit, scroll or pinch to zoom, Space to play or pause, double-click to reset the view, F for fps and backend.
