WebGPU Lab

Two small browser demos that explain how AI agents are kept honest, built from two of my own projects. Gatekeeper shows an agent's tool calls flowing through a reference monitor that allows, flags or blocks each one before it runs. Delegation Tree shows a chain of agents where every hop may only narrow the authority it received — widening a scope is refused before any token is issued. Everything renders with WebGPU when the browser supports it and falls back to Canvas2D when it does not, so the idea is always visible.

Particles are tool calls travelling toward a policy gate: allowed calls pass, flagged calls slow down and change shape, blocked calls break apart at the gate.

What is actually running

These are not mock-ups. The gatekeeper demo re-implements SENTRIX's capability policy (AgentPolicy.check_tool) and its injection classifier patterns, so each verdict and each reason string is computed live in your browser. The delegation demo uses AgentIAM's real narrowing rules from scope_utils.py and the real rejection message from attenuate.py, over the delegation chain from the project's own demo seed.

Tool calls, arguments and payload wording come from those repositories. Where a sequence had to be composed for the demo, the interface labels it as illustrative sample data. No secrets, tokens or live scan results are included.

Browser support

WebGPU needs a recent browser: Chrome/Edge 113+, Safari 18+, or Firefox with WebGPU enabled.

  • With WebGPU: instanced-quad rendering on the GPU, drawn by a small shared renderer (shared/gpu.js).
  • Without WebGPU: the same scene is drawn with a Canvas2D fallback, and a banner explains why.
  • With prefers-reduced-motion enabled, the simulation starts paused with a visible Play button.
  • Every demo is keyboard accessible and never relies on colour alone to convey a decision.
