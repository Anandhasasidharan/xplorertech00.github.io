Three.js Lab

Two small browser demos that explain how AI agents are kept honest, built from two of my own projects. Gatekeeper shows an agent's tool calls streaming through a reference monitor that allows, flags or blocks each one before it runs. Delegation Tree shows a chain of agents where every hop may only narrow the authority it received — widening a scope is refused before any token is issued. Both are built with Three.js and vanilla JavaScript, rendering with WebGPU where the browser supports it and WebGL 2 otherwise.

What is actually running

These are not mock-ups. The gatekeeper demo re-implements SENTRIX's capability policy (AgentPolicy.check_tool) and its injection classifier patterns, so each verdict and each reason string is computed live in your browser. One caveat: the classifier is a simplified port — it uses SENTRIX's pattern matching only and does not include the project's embedding classifier, so it recognises known patterns rather than paraphrases.

The delegation demo uses AgentIAM's real narrowing rules from scope_utils.py and the real rejection message from attenuate.py, over the delegation chain from the project's own demo seed.

Tool calls, arguments and payload wording come from those repositories. Where a sequence had to be composed for the demo, the interface labels it as illustrative sample data. No secrets, tokens or live scan results are included.

Rendering and controls

Both demos are Three.js scenes drawn by WebGPURenderer: WebGPU when the browser has it, WebGL 2 when it does not. Each page is one self-contained HTML file — the Three.js modules are bundled and inlined, so nothing is fetched at runtime.

  • Drag to orbit, scroll or pinch to zoom, double-click or Reset view to recentre.
  • Space plays or pauses. With prefers-reduced-motion the demos start paused, with a visible Play button.
  • F shows the frame rate and which backend is active; the Quality button turns bloom and trails off, and the demos drop to Low quality by themselves if frames stay slow.
  • Add ?backend=webgl to the URL to force the WebGL 2 backend.
  • Every demo is keyboard accessible and never relies on colour alone to convey a decision.

Chrome and Edge expose WebGPU by default from version 113 (on Linux it depends on hardware and drivers). Other browsers vary — Safari enables it by default from version 26 on macOS 26 Tahoe or later, and Firefox keeps it behind a flag outside Windows — so WebGL 2 is used when WebGPU is not available.
